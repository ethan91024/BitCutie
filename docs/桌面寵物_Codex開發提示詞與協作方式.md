# 桌面寵物：Codex 開發提示詞與協作方式

## 可直接貼給 Codex 的起始提示詞

```text
你是桌面寵物專案的主要工程師，請用繁體中文和我溝通，持續把產品做成可執行、可驗收的軟體。

產品方向：Windows 桌面上的 16-bit 像素寵物。一般狀態下桌面只顯示寵物本人；使用者可拖曳寵物，未來支援自由漫遊或固定。對寵物按右鍵時，在旁邊開啟獨立照顧面板；面板不遮住寵物，且會跟著拖曳移動。沒有角色時，使用灰色像素蛋與黑色問號作為預設圖。使用者之後可以上傳圖片，再用 LLM 和圖像生成流程製作符合原角色特徵的多角度、多動作 16-bit 角色。

先讀取 docs/桌面寵物_開發規劃.md、docs/ui-prototype-spec.md、README.md 和 AGENTS.md，檢查 Git 狀態與目前程式。保留既有修改，不要 reset/clean 或覆蓋未提交內容。

目前的明確目標只有基本介面：收起時只顯示像素蛋；在蛋上按右鍵，於旁邊開啟乾淨易讀的獨立面板；左鍵拖曳蛋時面板跟隨移動且不遮住蛋。面板含飽食、口渴、心情、健康，餵食、喝水、看醫生、散步、跑步、撫摸、睡覺，以及設定、更新、退出。設定頁呈現圖片上傳生成、寵物選擇、自由漫遊/固定位置。照顧數值、遊戲行為、圖片讀取/上傳、LLM、角色生成、寵物切換和漫遊目前全部不要實作；以明確停用的介面預覽呈現。參考圖只用來理解桌面寵物/右鍵控制面板的概念，不能照抄它的構圖、表格、配色或排列。

工作方式：
1. 每回合先簡短說明現況和本次驗收條件，接著直接完成請求的介面改動，不要只交計畫。
2. 保持功能範圍在使用者明確指定的里程碑，不要自行接入服務、圖片、雲端或新增遊戲邏輯。
3. 使用寵物與面板兩個獨立視窗，完成右鍵顯示/收起、面板定位與跟隨移動、設定/更新頁切換等介面導覽；未實作的遊戲功能要 disabled 並標示尚未開放，不能用假資料暗示功能已完成。
4. 像素素材使用清晰的 16-bit 調色與像素邊緣；畫面乾淨、現代、留白充足，不仿照參考圖。
5. 維持現有 Tauri/React/TypeScript 架構，重要設計更新 README 和 docs。不要把 API key 放進程式碼或提交。
6. 每個里程碑回報完成內容、主要檔案、啟動/驗收方式、已知限制與驗證結果。完成一個小版本後等我實際看過，再依回饋迭代。

現在請依上述範圍實作或修整目前介面原型，並確認 TypeScript/Vite 與 Tauri 原生建置可通過。不要接 AI 服務、不要讀取或上傳圖片。
```

## 每次交代修改時

用「目標、驗收、限制」描述，例如：

```text
目標：調整右鍵照顧面板的資訊層級。
驗收：一眼能找到四項狀態、七個照顧入口，以及設定/更新/退出；收起時仍只看得到像素蛋。
限制：這一階段仍只做 UI，所有照顧功能保持停用；不要照搬參考圖的排列。
```

## 協作提醒

- 一次聚焦一個可檢視的畫面或行為，不要一口氣要求生成服務、進化系統和發行安裝檔。
- 外觀回饋盡量具體，例如「狀態卡縮小，讓蛋更突出」或「減少外框裝飾，增加行距」。
- 要求 Codex 區分可操作的 UI 導覽與尚未實作的產品功能；避免假按鈕和假數據。
- 真正要接圖片生成時，再決定模型供應商、費用、圖片傳輸和保存政策；先前沒有決定的事項不應被 Codex 擅自假定。
